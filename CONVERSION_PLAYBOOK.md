All Track A backend domains and all prototype frontend modules have been
ported. This document is retained as a reference for the mechanical pattern
that produced the monorepo — follow it when adding any new domain. The
pattern is deliberately repetitive so the monorepo stays coherent.

## §A — Remaining backend domains

Each Track A file redeclares its own `Base`, engine, `Tenant`, and `User`.
That is what causes the `Table 'tenants' is already defined` error if you
import them directly. Converting a file is a three-step process.

| Source file (loose script) | Target domain module | Router prefix |
| --- | --- | --- |
| ~~`meridian_track_a_4_stage_gate_governance.py`~~ | ~~`governance`~~ | ~~`/projects/{project_id}/stage-gates`~~ ✅ ported |
| ~~`meridian_track_a_6_commercial_change_control.py`~~ | ~~`commercial`~~ | ~~`/projects/{project_id}/commercial`~~ ✅ ported |
| ~~`meridian_track_a_7_design_management.py`~~ | ~~`design`~~ | ~~`/projects/{project_id}/design`~~ ✅ ported |
| ~~`meridian_track_a_8_document_control.py`~~ | ~~`documents`~~ | ~~`/projects/{project_id}/documents`~~ ✅ ported |
| ~~`meridian_track_a_9_meetings_and_accountability.py`~~ | ~~`accountability`~~ | ~~`/projects/{project_id}/meetings`~~ ✅ ported |
| ~~`meridian_track_a_10_orat_and_handover.py`~~ | ~~`orat`~~ | ~~`/projects/{project_id}/orat`~~ ✅ ported |
| ~~`meridian_track_a_11_reporting_and_archive.py`~~ | ~~`reporting`~~ | ~~`/projects/{project_id}/reporting`~~ ✅ ported |
| ~~`meridian_track_a_12_search_ingestion.py`~~ | ~~`search`~~ | ~~`/projects/{project_id}/search`~~ ✅ ported |

### Step 1 — extract the models

1. Open the Track A file.
2. Copy every `class X(Base, ...):` definition into
   `backend/app/models/<domain>.py`.
3. **Delete** any local `Base = declarative_base()` / `class Tenant` /
   `class User` — they already exist in `app/models/core.py`.
4. Replace the `Base` import with:
   ```python
   from app.db.base import Base, TenantScopedMixin, TimestampMixin
   ```
5. Move any enum classes to `app/models/enums.py` (they are reused by schemas
   and routers).
6. Add the module's imports to `backend/app/models/__init__.py` — this is
   what Alembic's `env.py` scans.

### Step 2 — write Pydantic schemas

For every ORM model, produce **three** Pydantic classes in
`backend/app/schemas/<domain>.py`:

- `XCreate` — payload for POST, excludes server-owned fields
  (`id`, `tenant_id`, timestamps).
- `XUpdate` — every field `Optional`, uses `exclude_unset=True` on the router.
- `XRead(TimestampedOrm)` — response shape, inherits `from_attributes=True`.

Use `app.schemas.common` for reusable fragments.

### Step 3 — convert the router

Copy the `FastAPI()` route handlers from the Track A file into
`backend/app/api/routes/<domain>.py`. Then:

1. Replace `app = FastAPI()` with `router = APIRouter(prefix="/...")`.
2. Replace every `Depends(get_db)` / `Depends(get_current_user)` with the
   Meridian deps:
   ```python
   from app.api.deps import (
       CurrentPrincipal,
       get_current_principal,
       get_project_for_edit,
       get_project_for_view,
   )
   ```
3. Wrap write endpoints with the project dependency to enforce tenant
   isolation. **Never** trust `project_id` from the payload.
4. Call `write_audit_log(...)` on every write (create / update / delete). See
   `app/api/routes/projects.py` for the reference.
5. Commit once per request, not per row.

Finally, register the new router in `backend/app/api/router.py`:

```python
from app.api.routes import governance
api_router.include_router(governance.router, tags=["governance"])
```

And write an Alembic migration:

```bash
cd backend
alembic revision --autogenerate -m "governance tables"
alembic upgrade head
```

Review the autogenerated migration — autogenerate cannot see `is_critical:
Mapped[Optional[bool]]` columns without an explicit `server_default`, so verify
each column before committing.

### Step 4 — update the module registry

In `backend/app/api/routes/system.py`, flip `is_enabled: true` on the matching
entry. The frontend sidebar picks this up on the next page load — no
redeployment required.

## §B — Frontend modules

The `meridian app/` folder contains the JSX prototype modules. All have been
wired through to Next.js App Router pages.

| Prototype JSX | Target route | Data source |
| --- | --- | --- |
| ~~`module_04_stage_gate_governance.jsx`~~ | ~~`/stage-gates`~~ | ~~governance API~~ ✅ ported |
| ~~`module_06_commercial.jsx`~~ | ~~`/commercial`~~ | ~~commercial API~~ ✅ ported |
| ~~`module_07_design_management.jsx`~~ | ~~`/design`~~ | ~~design API~~ ✅ ported |
| ~~`module_08_document_control.jsx`~~ | ~~`/documents`~~ | ~~documents API~~ ✅ ported |
| ~~`module_09_meetings_actions.jsx`~~ | ~~`/meetings`~~ | ~~accountability API~~ ✅ ported |
| ~~`module_10_orat.jsx`~~ | ~~`/orat`~~ | ~~orat API~~ ✅ ported |
| ~~`module_11_reporting.jsx`~~ | ~~`/reporting`~~ | ~~reporting API~~ ✅ ported |
| ~~`module_12_search.jsx`~~ | ~~`/search`~~ | ~~search API~~ ✅ ported |

Conversion pattern (use `dashboard/page.tsx` as reference):

1. Create `src/app/<route>/page.tsx` as an **async server component**.
2. Move the JSX body into a small `<DomainView>` client component under
   `src/components/domains/<domain>/`. Mark it `"use client"` only if it has
   local state; everything else stays server-rendered.
3. Replace mock data from the JSX prototype with an `endpoints.<x>()` call.
   Add the wrapper to `src/lib/api/endpoints.ts` so URLs live in one place.
4. Swap bespoke colour palettes for the Tailwind tokens in
   `tailwind.config.ts` (`meridian-*`, `accent-*`).
5. Replace the prototype's local state shape with the `types.ts` interfaces so
   the backend response flows end-to-end without hand-massaging.

## §C — Check list before merging a domain

- [ ] Models import from `app.db.base.Base` — not a local `declarative_base`.
- [ ] All columns inherit `TenantScopedMixin` (except cross-tenant tables).
- [ ] Alembic migration generated and reviewed; server-defaults for bools.
- [ ] Every router endpoint runs through `get_project_for_view` / `_edit` /
      `_admin` — no bare `db.query` that ignores `tenant_id`.
- [ ] `write_audit_log` called on every write path.
- [ ] `app/api/router.py` registers the new router.
- [ ] `app/models/__init__.py` imports the new model module.
- [ ] `system.py` module registry flipped to `is_enabled: true`.
- [ ] Frontend page added under `src/app/<route>/page.tsx`.
- [ ] `endpoints.ts` wrapper added with types from `types.ts`.
- [ ] Sidebar icon resolvable in `Sidebar.tsx`'s `ICONS` map.

If every box above is ticked, the domain is production-ready at the same level
as the reference four (core / project setup / schedule / risks).
